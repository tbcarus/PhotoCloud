# PhotoCloud — правила работы с кодовыми агентами

## 1. Контекст проекта

PhotoCloud состоит из Server (Java/Spring Boot), Android Client (Kotlin) и системной документации.
`system-spec/docs/spec/system/` — основная рабочая спецификация поведения и принятых решений.

## 2. Общие принципы разработки

- Используй существующую архитектуру, соглашения и механизмы проекта.
- Предпочитай простые решения с минимальным количеством изменений.
- Не вводи новые слои, абстракции, зависимости или универсальные механизмы без обоснованной необходимости.
- Не расширяй поставленную задачу на соседние функции.
- Не меняй существующее поведение, API и формат данных без необходимости.
- Заделы на будущее должны быть обоснованы

## 3. Конфигурация

- Конфигурационный параметр и его значение по умолчанию должны иметь один источник истины.
- Для Server значения по умолчанию задаются в YAML; Java-классы `ConfigurationProperties` выполняют привязку и валидацию, не дублируя defaults.
- Не создавай новые параметры конфигурации без реальной необходимости.
- Не используй магические константы вместо уже существующей конфигурации.

## 4. Качество

- Изменения должны сопровождаться подходящими тестами.
- Не удаляй и не ослабляй существующие проверки ради успешного прохождения тестов.
- Особое внимание уделяй транзакциям, конкурентности, сохранности данных, обработке ошибок и восстановлению.
- Проверяй не только успешный сценарий, но и значимые отказы.
- Комментарии в коде — краткие, на русском языке, только когда они помогают понять неочевидное решение.

## 5. Git и документация

- Не создавай коммиты без запроса.
- При изменении системного поведения актуализируй system/. Если код расходится с утверждённым поведением, не меняй спецификацию под код без согласования.

## 6. Отчёт

- После выполнения кратко сообщи, что изменено, какие проверки выполнены, что не удалось проверить и какие вопросы остались.
- Не выдавай непроверенные предположения за установленные факты.
