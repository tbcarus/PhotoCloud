# Аккаунт и доступ

## 1. Регистрация

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [AUTH-REG](../system/02-account-and-auth.md#auth-reg)

Пользователь создаёт аккаунт с помощью email и пароля. Если введённые данные допустимы и такой email ещё не занят, система создаёт новый неактивированный аккаунт и отправляет письмо подтверждения. Автоматического входа после регистрации нет.

Если email уже принадлежит существующему аккаунту, новый аккаунт не создаётся.

## 2. Подтверждение регистрации

**Status:** AS-IS  
**Availability:** SERVER_ONLY  
**System:** [AUTH-ACT](../system/02-account-and-auth.md#auth-act)

После регистрации система отправляет письмо со ссылкой подтверждения на указанный email. Пользователь открывает эту ссылку вне Android. После успешного подтверждения аккаунт становится активным и может использоваться для входа.

До подтверждения email войти в аккаунт нельзя. Просроченная, неверная или уже использованная ссылка аккаунт не активирует.

## 3. Повторная отправка подтверждения

**Status:** AS-IS  
**Availability:** STUB  
**System:** [AUTH-RESEND](../system/02-account-and-auth.md#auth-resend)

Если письмо подтверждения не дошло, было потеряно или его ссылка истекла, рабочего пользовательского пути повторной отправки сейчас нет. Повторная регистрация с тем же email также не решает проблему, потому что аккаунт уже существует.

## 4. Вход

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [AUTH-LOGIN](../system/02-account-and-auth.md#auth-login)

Активированный пользователь входит по email и паролю. После успешного входа Android сохраняет локальную сессию, и приложение может выполнять защищённые действия и автоматический backup от имени этого пользователя.

Неактивированный или заблокированный аккаунт новый вход выполнить не может.

## 5. Продолжение сессии

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [AUTH-ACCESS](../system/02-account-and-auth.md#auth-access) · [AUTH-REFRESH](../system/02-account-and-auth.md#auth-refresh)

Во время обычной работы приложение использует сохранённую сессию автоматически. Если текущий доступ истёк, Android пытается продлить его и один раз повторить исходное действие. Пока продление успешно, пользователю не требуется входить заново.

Есть существенная текущая ветка: некоторые ошибки Server при продлении сессии приводят к удалению локальной сессии даже тогда, когда причина могла быть временной. После этого пользователь должен войти снова.

## 6. Ограничение доступа неактивного или заблокированного аккаунта

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [AUTH-BLOCK](../system/02-account-and-auth.md#auth-block)

Неактивированный или заблокированный аккаунт не может выполнить новый вход. При этом сама блокировка не прекращает мгновенно уже существующий доступ, выданный до блокировки.

## 7. Выход из текущей сессии

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [AUTH-LOGOUT](../system/02-account-and-auth.md#auth-logout)

Пользователь может выйти из текущей сессии через Android. После полученного ответа приложение удаляет локальную сессию и пересматривает работу фонового backup.

Уже выполняющаяся операция может завершиться не мгновенно, а ранее выданный кратковременный доступ на Server не отзывается сразу только из-за выхода.

## 8. Управление остальными сессиями

**Status:** AS-IS  
**Availability:** SERVER_ONLY  
**System:** [AUTH-LOGOUT-ALL](../system/02-account-and-auth.md#auth-logout-all) · [AUTH-LOGOUT-OTHERS](../system/02-account-and-auth.md#auth-logout-others)

Server умеет завершать все серверные сессии пользователя или все сессии кроме выбранной. В Android пользовательского управления этими сессиями сейчас нет.

## 9. Восстановление забытого пароля

**Status:** AS-IS  
**Availability:** SERVER_ONLY  
**System:** [AUTH-RESET](../system/02-account-and-auth.md#auth-reset)

На Server существует цепочка восстановления пароля по email: можно запросить сброс, получить письмо и подтвердить установку нового пароля.

Как функция приложения этот путь незавершён: Android не имеет рабочего экрана «забыли пароль», а ссылка из письма не приводит пользователя к работающей форме смены пароля. Повторная отправка письма восстановления также не работает.

После смены пароля уже существующие сессии автоматически не завершаются.
