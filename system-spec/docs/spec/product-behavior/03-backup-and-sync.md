# Backup и синхронизация

## 1. Автоматический backup новой фотографии

**Status:** CHECK 
**Availability:** END_TO_END  
**System:** [BACKUP-NEW](../system/04-backup-and-sync.md#backup-new) · [BACKUP-BACKGROUND](../system/04-backup-and-sync.md#backup-background)

PhotoCloud автоматически сохраняет новые фотографии Android на выбранный Server. 
Это односторонний backup: приложение отправляет локальные фотографии и видео на Server, 
но на данный момент не поддерживает полноценную обратную синхронизацию удалённой библиотеки на устройство.

Для автоматической работы нужны выбранный Server, пользовательская сессия и разрешение Android на чтение фотографий. 
При выполнении этих условий приложение реагирует на изменения и дополнительно выполняет периодические проверки.

## 2. Какие фотографии попадают в автоматический backup

**Status:** CHECK 
**Availability:** ANDROID_ONLY  
**System:** [BACKUP-DISCOVER](../system/04-backup-and-sync.md#backup-discover)

Когда Android обнаруживает новую подходящую фотографию или видео файл в папке камеры, он добавляет её в локальную очередь обработки.
Очередь обработки представляет собой локальную базу данных, в которую попадают все фото и видео файлы папки камеры.
Для соответствующей работы должна быть предусмотрена система статусов. А для точной идетификации файлов вычисление хэш суммы.

Сейчас автоматически рассматриваются изображения из DCIM и его подпапок. Видео и изображения вне этой области в обычный backup не входят.

## 3. Проверка, сохранена ли фотография раньше

**Status:** OPEN  
**Availability:** END_TO_END  
**System:** [BACKUP-EXISTING](../system/04-backup-and-sync.md#backup-existing) · [BACKUP-TARGET](../system/04-backup-and-sync.md#backup-target)

Перед передачей фотографии приложение проверяет, представлено ли это содержимое уже в целевой серверной папке.

Если фотография уже известна Server, повторная передача не выполняется, 
а Android считает её сохранённой. Android должен сделать запрос существования файла на сервере, решение о существовании файла
осуществляется сервером на основе хэш суммы, целевой папки, пользователя.
Этот результат подтверждает состояние по логике приложения, 
но сам по себе не является полной проверкой физической сохранности данных на Server.
Обычные уже сохранённые фотографии затем автоматически заново не сверяются.

## 4. Загрузка новой фотографии

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [BACKUP-UPLOAD](../system/04-backup-and-sync.md#backup-upload)

Если Server не знает фотографию в целевой папке, Android передаёт её на Server. После успешного сохранения и ответа Server Android отмечает фотографию как сохранённую.

## 5. Повторная отправка и потерянное подтверждение

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [BACKUP-DUPLICATE](../system/04-backup-and-sync.md#backup-duplicate)

Если Server получает повторную отправку того же содержимого в ту же папку, он возвращает уже существующий файл вместо создания ещё одной логической записи.

Благодаря этому ситуация, когда Server уже сохранил фотографию, но Android не получил подтверждение, 
обычно завершается следующей попыткой без создания второй записи в той же папке.

## 6. Размещение фотографий на Server

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [BACKUP-TARGET](../system/04-backup-and-sync.md#backup-target)

Для обычного backup приложение ориентируется на системную папку CAMERA. 
Если её ещё нет, первый успешный upload обычной фотографии позволяет Server создать её автоматически. 
Локальные подпапки DCIM не превращаются в аналогичное дерево папок на Server.

Выбор места назначения перед предварительной проверкой и непосредственно перед upload выполняется отдельно. 
При некоторых ошибках повторного определения папки Server может выбрать место назначения самостоятельно, 
поэтому фактический результат способен отличаться от ожидавшегося Android.

## 7. Запуск backup в фоне

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [BACKUP-BACKGROUND](../system/04-backup-and-sync.md#backup-background)

Изменение локальных фотографий может запустить backup вскоре после события. Дополнительно существует периодический запуск примерно раз в час, но это не обещание точного времени: фактический запуск зависит от Android и текущих условий.

Для обычной фоновой работы достаточно доступной сети. Режима «только Wi-Fi» сейчас нет.

## 8. Повторы после ошибок

**Status:** AS-IS  
**Availability:** ANDROID_ONLY  
**System:** [BACKUP-RETRY](../system/04-backup-and-sync.md#backup-retry)

Временная ошибка может отложить обработку и привести к следующей попытке. Некоторые ошибки конкретной фотографии автоматически восстанавливаются ограниченное число раз, а другие остаются в состоянии ошибки.

В интерфейсе сейчас нет ручной команды Retry/Sync now для такой фотографии. Ошибка одного нового файла также способна задержать другие ожидающие отправки фотографии.

## 9. Продолжение после остановки приложения или перезагрузки устройства

**Status:** AS-IS  
**Availability:** ANDROID_ONLY  
**System:** [BACKUP-RESTART](../system/04-backup-and-sync.md#backup-restart) · [BACKUP-DUPLICATE](../system/04-backup-and-sync.md#backup-duplicate)

Локальная очередь переживает обычную остановку процесса, но часть рабочего контекста хранится только в памяти. После перезапуска или перезагрузки фоновой работе может не хватать текущего адреса Server; тогда обработка не продвигается, пока приложение снова не восстановит адрес через экран Network.

После восстановления контекста очередь может продолжиться. Если фотография уже успела сохраниться на Server до прерывания, повторная попытка обычно завершает локальное состояние через ветку уже существующего файла.

## 10. Изменение ранее известной фотографии

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [BACKUP-CHANGE](../system/04-backup-and-sync.md#backup-change)

Если ранее известная фотография изменилась так, что Android распознал изменение, она проходит backup заново. Новое содержимое может создать новую серверную копию.

Прежняя серверная копия автоматически не удаляется и не связывается с новой как управляемая версия.

## 11. Удаление фотографии с телефона

**Status:** AS-IS  
**Availability:** ANDROID_ONLY  
**System:** [BACKUP-DELETE](../system/04-backup-and-sync.md#backup-delete)

Если фотография исчезла из видимой приложению локальной коллекции, запись о ней удаляется из локальной очереди. Серверная копия при этом остаётся.

Поэтому удаление фотографии на телефоне сейчас **не означает удаление её копии из PhotoCloud на Server**.

Если та же фотография позднее снова становится видимой Android, она рассматривается как новая локальная запись и проходит обычный путь проверки и backup заново.

## 12. Имена и метаданные фотографий

**Status:** AS-IS  
**Availability:** END_TO_END  
**System:** [BACKUP-METADATA](../system/04-backup-and-sync.md#backup-metadata)

Android и Server формируют сведения о фотографии независимо. Server сохраняет полученные данные и при возможности извлекает дату съёмки и сведения об изображении; отсутствие таких сведений не препятствует самому backup.

Локальные и серверные имя, время и метаданные поэтому могут отличаться даже после успешного сохранения.
