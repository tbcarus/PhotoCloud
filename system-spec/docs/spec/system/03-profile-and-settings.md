# Профиль и настройки

В Android есть рабочая настройка соединения на Network и краткие сведения о входе на Auth. Вкладки Profile и Settings открываются, но содержат только заглушки. Server умеет читать профиль, но Android его не запрашивает.

Используемая модель: [User](01-system-model.md#user), [TokenPair](01-system-model.md#token-pair) и [NetworkState](01-system-model.md#network-state).

<a id="profile-auth"></a>

## PROFILE-AUTH — Сведения о текущем входе в Android

**Status:** AS-IS

**Availability:** ANDROID_ONLY

### Назначение

Показать пользователю, какая локальная сессия выбрана.

### Текущее поведение

Пользователь открывает Auth при сохранённой паре.

1. Android показывает email, декодированный из subject access, и действия Logout/Test Auth.
2. После очистки пары экран переключается на форму входа.

Пользователь видит сведения о локальной сессии; Server profile API не вызывается.

### Текущие ограничения

Декодирование email на клиенте не проверяет подпись или срок токена и не подтверждает состояние профиля. Доступ и verification описаны в [AUTH-ACCESS](02-account-and-auth.md#auth-access).

<a id="profile-view"></a>

## PROFILE-VIEW — Чтение серверного профиля

**Status:** AS-IS

**Availability:** SERVER_ONLY

### Назначение

Получить текущие сведения об аккаунте.

### Текущее поведение

Внешний клиент запрашивает профиль с действующим access.

1. Server читает текущего пользователя.
2. Возвращает [представление профиля UserDto](01-system-model.md#api-projections): поля User, кроме passwordHash.

Чтение профиля не изменяет данные.

### Ошибки и recovery

Действуют обычные ошибки авторизации или сети. Android не предоставляет recovery или отображение для этого API.

### Текущие ограничения

Отдельный экран Profile в Android показывает только текст Profile. Регистрация не задаёт displayName.

<a id="profile-edit"></a>

## PROFILE-EDIT — Изменение профиля

**Status:** AS-IS

**Availability:** STUB

### Назначение

Зафиксировать отсутствие рабочего редактирования профиля.

### Текущее поведение

Внешний клиент вызывает PATCH profile или пользователь открывает Profile в Android.

Server возвращает 501; присланные поля не применяются. Android показывает текстовую заглушку без формы.

Профиль не изменяется.

### Текущие ограничения

Рабочая операция чтения Server описана отдельно в [PROFILE-VIEW](03-profile-and-settings.md#profile-view); заглушка изменения не означает отсутствия чтения.

<a id="settings-user"></a>

## SETTINGS-USER — Пользовательские настройки

**Status:** AS-IS

**Availability:** STUB

### Назначение

Определить текущее состояние Settings.

### Текущее поведение

Пользователь открывает Settings либо внешний клиент вызывает чтение или изменение настроек Server.

Android показывает только текст Settings. Server GET/PATCH profile/settings возвращают 501, не читают и не сохраняют настройки.

Пользовательские настройки этим путём недоступны.

### Текущие ограничения

В UI нельзя включать/выключать sync, требовать Wi-Fi или зарядку, выбирать интервал, правила retry, папки/media, максимальный размер или уровень логов. Рабочие IP/port на Network описаны в [SETTINGS-NETWORK](03-profile-and-settings.md#settings-network).

<a id="settings-network"></a>

## SETTINGS-NETWORK — Настройка адреса и проверка связи

**Status:** AS-IS

**Availability:** END_TO_END

### Назначение

Выбрать Server для запросов Android.

### Текущее поведение

Пользователь открывает стартовую вкладку Network, вводит IPv4/port и нажимает Test.

1. Android проверяет IPv4 и непустоту port, убирает пробелы по краям и формирует HTTP-адрес.
2. Отправляет public test. Успех сохраняет IP/port и назначает текущий URL, результат показывается в диалоге.
3. При следующем создании Network UI сохранённый адрес восстанавливается до автоматического test; тогда же пересматриваются условия фона.

После успеха последующие запросы используют выбранный адрес Server.

### Развилки и условия

Неуспешный пользовательский Test оставляет прежний URL. Успешный ручной Test сам по себе не пересматривает фон; для этого используются события из [BACKUP-BACKGROUND](04-backup-and-sync.md#backup-background).

### Ошибки и recovery

Порт проверяется только на непустоту; некорректное число/диапазон может вызвать исключение создания соединения и оставить индикатор загрузки без штатного завершения. Public ping не проверяет готовность БД, хранилища или SMTP.

### Текущие ограничения

Нет HTTPS/domain/IPv6/path-prefix selector. При разрешённом соединении учётные данные и изображения передаются без TLS; реальная доступность LAN/proxy не установлена. Смена адреса не очищает credentials или очередь ([SYSTEM-SCOPE](07-system-rules-and-recovery.md#system-scope)). Headless восстановление URL отсутствует ([BACKUP-RESTART](04-backup-and-sync.md#backup-restart)).

### Нерешённый вопрос

Продуктовый сценарий транспорта и размещения Server не принят. Реальные endpoint/revision, состояние БД, proxy/forwarded origin и нестандартизованные framework error responses не проверены.

<a id="profile-absent"></a>

## PROFILE-ABSENT — Смена email, avatar и удаление аккаунта

**Status:** AS-IS

**Availability:** NOT_PRESENT

### Назначение

Зафиксировать границу управления аккаунтом.

### Текущее поведение

Текущая система не предоставляет пользовательского или API-сценария смены email, avatar или удаления аккаунта.

Эти действия нельзя выполнить как функцию PhotoCloud.

### Текущие ограничения

Наличие пользователя в модели или возможность внешнего изменения БД не являются функцией приложения. Reset пароля существует отдельно ([AUTH-RESET](02-account-and-auth.md#auth-reset)).
