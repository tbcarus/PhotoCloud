# Уведомления

Уведомление сообщает одному пользователю о событии на Server, которое его касается, и хранит, прочитал ли он его. Это общая подсистема: источником события может быть любая операция Server. Сейчас уведомления создаёт только выдача нового USER-доступа ([SHARING-USER-MANAGE](06-sharing-and-access.md#sharing-user-manage)).

Используемая модель: [Notification](01-system-model.md#notification), [NotificationType](01-system-model.md#notification-type), [NotificationTargetType](01-system-model.md#notification-target-type), [User](01-system-model.md#user); представление — [NotificationDto](01-system-model.md#api-projections). Поля, типы и инварианты определены только в System Model.

<a id="notifications-rules"></a>

## Общие правила

**Типы.** Создаётся только SHARE_GRANTED. BACKUP_FAILED и SYSTEM_MESSAGE зарезервированы в модели: Server их не создаёт, клиенты показывают их текст без специальных действий.

**Создание.** Уведомление создаёт Server внутри бизнес-операции, для которой оно предусмотрено: получатель, вид, заголовок и текст формирует Server, клиенты уведомления не создают. Текст — снимок на момент события на языке Server, без токенов, секретов и путей хранения. Notification.targetType и Notification.targetId указывают объект события, если он есть.

**Транзакционность.** Уведомление записывается в той же транзакции, что и операция: откат или отказ операции не оставляет уведомления, а успешная операция не может завершиться без него. Очередей, повторной отправки и асинхронной доставки нет.

**История.** Записи не удаляются вместе с объектом события: удаление файла или папки, отзыв, истечение или отказ от Share уведомление не меняют. Notification.title и Notification.body не обновляются при переименовании объекта. Запись удаляется только вместе с получателем. Пользовательского удаления, срока хранения и очистки нет.

**Цель — не право.** Notification.targetId — только указатель для перехода. Доступ к объекту по-прежнему определяет [ACCESS-READ](06-sharing-and-access.md#access-read): уведомление не открывает удалённый или более недоступный объект и не расширяет права получателя.

**Изоляция.** Каждое уведомление видно и меняется только его получателем. Чужой ID неотличим от отсутствующего. Состояние прочтения хранит только Server: все сессии и устройства пользователя видят один Notification.readAt.

<a id="notifications-read"></a>

## NOTIFICATIONS-READ — Получение и прочтение уведомлений

**Status:** IMPLEMENTING

**Availability:** END_TO_END

### Назначение

Сообщить пользователю о событиях, касающихся его, — сейчас о новом USER-доступе — и дать отмечать прочитанное.

### Текущее поведение

Пользователь открывает уведомления в Android или выполняет запрос `/api/v1/notifications` с действующим access ([AUTH-ACCESS](02-account-and-auth.md#auth-access)). Уведомления создаёт Server по [общим правилам](08-notifications.md#notifications-rules).

**Список** (`GET`, page и size как у [FILES-LIST](05-file-library.md#files-list)): страница NotificationDto текущего пользователя от новых к старым по createdAt, при равном времени — по убыванию id. Уведомление показывается независимо от того, существует ли ещё объект и действует ли Share.

**Количество непрочитанных** (`GET /unread-count`): число уведомлений текущего пользователя без readAt; при отсутствии уведомлений — 0.

**Прочтение одного** (`PATCH /{id}/read`): readAt получает текущее время Server; уже прочитанное сохраняет исходный readAt. Ответ — NotificationDto. Повтор не меняет данные.

**Прочтение всех** (`PATCH /read-all`): одной операцией readAt получают все непрочитанные уведомления текущего пользователя; у прочитанных readAt не меняется. Ответ — 204, повтор не меняет данные.

<a id="notifications-read-android"></a>

**Android.** Колокольчик в верхней панели приложения виден при входе в аккаунт на всех экранах, кроме экрана входа; без сессии его нет. Число непрочитанных берётся из запроса количества: при 0 — колокольчик без индикатора, иначе число, больше 99 — «99+». Нажатие открывает экран «Уведомления» поверх текущей вкладки; нижняя панель не меняется.

1. Экран показывает список от новых к старым в порядке Server: заголовок и текст из ответа Server, дата и время создания в часовом поясе устройства. Непрочитанное отмечено точкой и полужирным заголовком. Страницы по 50 подгружаются при прокрутке, всю историю Android не загружает. Пустой список — «Уведомлений пока нет»; сбой связи или Server — сообщение с «Повторить».
2. Нажатие на непрочитанное уведомление отправляет прочтение одного; пока запрос идёт, другие нажатия и «Прочитать все» недоступны. После успеха строка заменяется уведомлением из ответа, счётчик перечитывается. При отказе связи или Server уведомление остаётся непрочитанным, показывается причина, перехода нет. Прочитанное уведомление повторно на Server не отправляется.
3. «Прочитать все» отправляет прочтение всех; после 204 список перечитывается с первой страницы и счётчик обновляется. При отказе состояние не меняется, показывается причина.

<a id="notifications-read-update"></a>

**Обновление Android.** Push нет; данные запрашиваются, пока приложение на экране.
- Счётчик: сразу после входа в аккаунт, при возврате приложения на передний план, после действий прочтения и раз в 90 секунд, пока приложение на переднем плане; при сворачивании опрос прекращается.
- Цикл опроса один на процесс. Новый запрос счётчика не начинается, пока выполняется предыдущий; после прочтения прежний запрос отменяется, и применяется только последний ответ.
- Список перечитывается при каждом показе экрана, в том числе при возврате приложения на него.
- Прочтение в другой сессии того же пользователя видно после очередного обновления: Android использует readAt из ответа Server и собственного состояния прочтения не хранит.

<a id="notifications-read-navigation"></a>

**Переход по цели.** После прочтения уведомление SHARE_GRANTED с targetType и targetId открывает ресурс в разделе «Доступно мне» вкладки Library ([вход из уведомления](05-file-library.md#shared-with-me-from-notification)): Android ищет ресурс среди прямых действующих доступов текущего пользователя, отдельного запроса к объекту по targetId нет.
- Папка открывается корнем предоставленного дерева: выше неё — только список «Доступно мне».
- Файл открывается существующим просмотром, плеером, PDF или внешним приложением, только для чтения.
- Недоступный ресурс даёт список «Доступно мне» с пояснением. Уведомление остаётся в истории, выхода из аккаунта нет.
- Back из Library возвращает к экрану уведомлений.
- Уведомления без цели, других и неизвестных видов показывают текст и только отмечаются прочитанными.

<a id="notifications-read-isolation"></a>

**Изоляция в Android.** Уведомления и счётчик хранятся только в памяти процесса, Room и настройки их не сохраняют. Смена адреса Server, пользователя или выход сбрасывают список и счётчик, отменяют запросы; ответы и переход прежней сессии отбрасываются. Открытый экран при новой сессии загружает список заново, без сессии предлагает вход.

### Ошибки и recovery

- 401 — запрос без действующего access. На Android 401/403 сбрасывают данные уведомлений; сами уведомления выход из аккаунта не выполняют, недействительный refresh обрабатывается общим механизмом ([AUTH-REFRESH](02-account-and-auth.md#auth-refresh)).
- 404 — уведомление отсутствует или принадлежит другому пользователю: ни содержимое, ни состояние чужого уведомления не меняются.
- 400 — отрицательный page или нулевой size.
- Сбой связи или Server на Android: при загрузке списка — «Повторить», при прочтении — уведомление остаётся непрочитанным, при опросе счётчика — прежнее значение до следующего обновления. 404 цели при переходе обрабатывает Library ([вход из уведомления](05-file-library.md#shared-with-me-from-notification)).

### Текущие ограничения

Каналов доставки, кроме запроса из Android, нет: push, email, WebSocket, системных уведомлений Android и фоновой доставки нет. Пока приложение свёрнуто, новое уведомление не появляется, а счётчик обновится только при возврате.

Android ищет ресурс уведомления только среди прямых доступов «Доступно мне». Объект внутри предоставленной папки, прямой доступ к которому отозван, не открывается переходом, хотя может читаться через папку. Поиск просматривает страницы списка доступов подряд, без ограничения их числа.

Уведомления об изменении срока, отзыве и истечении доступа, о новых файлах в общей папке и о публичных ссылках не создаются. Верхний предел size не задан.
