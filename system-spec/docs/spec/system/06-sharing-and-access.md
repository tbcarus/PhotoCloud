# Sharing и доступ

Совместного доступа к файлам и папкам сейчас нет. Существующие операции проверяют владельца независимо от возможностей структуры данных.

Используемая модель: [User](01-system-model.md#user), [Folder](01-system-model.md#folder), [RemoteFile](01-system-model.md#remote-file) и [StoredObject](01-system-model.md#stored-object).

<a id="access-owner"></a>

## ACCESS-OWNER — Доступ к собственным файлам и папкам

**Status:** AS-IS

**Availability:** SERVER_ONLY

### Назначение

Ограничить доступ к удалённой библиотеке текущим пользователем.

### Текущее поведение

Клиент выполняет защищённую операцию с файлом или папкой. Server установил пользователя по [AUTH-ACCESS](02-account-and-auth.md#auth-access).

1. Server ищет RemoteFile/Folder по ID вместе с текущим User.
2. Собственный объект передаётся соответствующей операции. Отсутствующий и чужой объект одинаково дают 404.
3. Для download достаточно владения RemoteFile; отдельная проверка ACL StoredObject не выполняется.

Клиент работает в своём логическом каталоге. Android использует эту проверку при backup, но не предоставляет отдельного UI управления доступом.

### Текущие ограничения

Роль ADMIN не даёт обхода проверки владельца; отдельных действующих операций по ролям нет. Модель допускает несовпадение владельцев связанных записей, но обычные upload/copy создают объекты одного владельца. Поведение удаления в таком состоянии описано в [FILES-DELETE](05-file-library.md#files-delete).

<a id="sharing-absent"></a>

## SHARING-ABSENT — Совместный доступ и публичные ссылки

**Status:** AS-IS

**Availability:** NOT_PRESENT

### Назначение

Однозначно установить наличие sharing в текущем PhotoCloud.

### Текущее поведение

В Android и Server нет API/UI совместного доступа, публичных ссылок, выдачи доступа другому пользователю или модели permissions/ACL для sharing. Обычные upload и copy не создают общих ссылок между владельцами; операции создания ссылки на существующий объект нет.

Пользователь не может поделиться файлом или папкой как функцией PhotoCloud.

### Текущие ограничения

Структура данных допускает несколько RemoteFile, ссылающихся на StoredObject. Реализованной функции sharing из этого не следует. Copy создаёт независимые байты ([FILES-COPY](05-file-library.md#files-copy)); наличие ветки удаления ссылки пользователем, не владеющим StoredObject, не доказывает предоставление совместного доступа.
